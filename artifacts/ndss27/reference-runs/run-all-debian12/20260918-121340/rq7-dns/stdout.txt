=== Conclusions ===

1. Bit-precision discrimination (the headline claim).
   Run A (QR-only)     -> AL taint = 0x00   (QR bit erased by & 0x78)
   Run B (OPCODE-only) -> AL taint = 0x0f   (OPCODE shifted to bits 0..3)
   Same byte position, opposite verdicts.  A byte-precision DTA cannot
   distinguish these two cases; microtaint discriminates them exactly.

2. Soundness and precision on the data register (AL).
   In all 4 runs, microtaint's predicted AL taint mask is bit-exact equal to the
   per-bit Unicorn ground truth: engine >= GT (no missed deps) AND
   engine <= GT (no over-tainting).

3. Run B vs Run C: precision in A is not bought by losing coverage in B.
   With OPCODE-only taint (B) the engine reports AL taint = 0x0f,
   identical to the whole-byte-tainted baseline (C) of 0x0f.
   The extra precision in Run A is therefore a refinement on top of
   correct byte-level behaviour, not a regression on it.

4. No spurious taint without a source.
   Run D feeds the same value (0x10) through the same sequence with
   no input taint.  The engine reports zero taint on every output register and flag.

5. Known caveat: EFLAGS over-tainting on the AND/SHR sequence.
   Microtaint reports condition flags as tainted in runs A/B/C even
   when the per-bit ground truth shows the flag does not depend on the
   tainted bits.  Specifically: A.OF, A.PF, B.OF, C.OF
   This is the family of issues the upstream test suite tracks under
   group G-A (constant-result idioms) and G-B (shift carry semantics).
   It does not affect the OPCODE-extraction result on AL, and the DNS
   dispatch in parse_flags reads `op` (a register), not these flags.
   But: any claim of "bit-exact precision on the entire architectural
   state" must be qualified -- the precision is exact on the data path,
   not on EFLAGS.
